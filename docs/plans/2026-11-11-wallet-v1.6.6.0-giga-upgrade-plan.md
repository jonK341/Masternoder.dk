# Wallet v1.6.6.0 Giga → v32.6.6.0 Exchange Mega Plan

## Goal Capsule

- **Objective:** Ship **MasterNoder2 Wallet v1.6.6.0** as a giga upgrade that turns the documented Top 50 agent technologies into real wallet / daemon / Qt / web capabilities people can feel — then extend that same Top50 catalog into **v32.6.6.0**, an exchange-grade mega wallet for crypto trading rails.
- **Means:** Map each of the 50 techs into a concrete wallet surface (daemon RPC, Qt UI, `/wallets` + profile wallet, sporks, monitoring). Land them in four version trains that culminate in **1.6.6.0**. After that, install Top50 **improvements / enrichments** as exchange-wallet modules (`X-01`…`X-50`) culminating in **32.6.6.0**.
- **Authority:** Product behavior wins over agent-scaffold leftovers. Do not ship empty `/api/agent-tech/*` stubs as the wallet upgrade.
- **Execution:** Daemon + Qt live in the MasterNoder2 release line; web/API glue, exchange controller, and download manifests live in this repo.
- **Stop:** Stop if a work item requires turning `SPORK_112` / `SPORK_113` / `SPORK_114` live by default, or if it mixes unrelated frontpage entertainment into the wallet binary.
## Why 1.6.6.0 — then 32.6.6.0

| Today | Gap | 1.6.6.0 (giga) | 32.6.6.0 (exchange mega) |
| ----- | --- | -------------- | ------------------------ |
| Wallet downloads at **mn2-wallet-v1.3.0.0** | Big jump past 1.4/1.5 needs a story | Version train 1.4 → 1.5 → 1.6 → **1.6.6.0 giga ship** | Post-giga train: exchange custody + trading wallet as **32.6.6.0** |
| Daemon **v1.3.1.0** (exchange/casino/payout/maintenance sporks) | Sporks exist; wallet UX still thin | Tech pillars become general wallet features | Same pillars **enriched** for live trading, deposits, withdrawals, venue rails |
| Top 50 techs exist as agent docs / DB schema | Mostly platform/agent scaffolding | Each tech maps to one wallet deliverable `W-*` | Each tech + its 12 improvements map to exchange enrichments `X-*` |
| Exchange exists as site product (`/exchange`, controller, casino bridge) | Wallet is not yet an exchange-grade trading client | Wallet stays MN2-native (send/stake/host) | Wallet becomes the **better crypto-exchange wallet**: trading desk, risk, PoR, venue failover |

Source catalog: `docs/50_AGENT_TECHS_COMPLETE.md` (50 techs × 12 improvement functions = 600 enrichment knobs).

## Product Contract

### Summary

A person running Wallet **v1.6.6.0** gets a hardened, observable, self-healing MN2 wallet: faster sync and RPC, safer keys and spend paths, live health/alerts, smart fee and anomaly help, and a web/Qt surface that mirrors Top25-grade telemetry without requiring agent dashboards.

### Requirements

- R1. Every Top50 tech maps to exactly one wallet deliverable ID (`W-01`…`W-50`) with owner surface: `daemon` | `qt` | `web` | `ops`.
- R2. Version trains ship: **1.4.0.0** (core rail), **1.5.0.0** (tools + scanners), **1.6.0.0** (monitors + navigation), **1.6.6.0** (advanced intelligence + integration + release).
- R3. `/wallets` and release manifests advertise **v1.6.6.0** with sha256 for daemon + Qt linux/win when the giga tag ships.
- R4. Existing sporks 112–115 stay human-gated. New wallet gates 116–121: money-moving default-off; `SPORK_118_ANOMALY_HARD_ENFORCE` defaults ON (fail closed).
- R5. Each train has falsifiable acceptance: RPC smoke, Qt smoke, web download row, and one regression suite.
- R6. After giga ships, every Top50 tech also maps to one exchange enrichment ID (`X-01`…`X-50`) installable into the better crypto-exchange wallet.
- R7. **v32.6.6.0** is the exchange-mega tag: trading desk + custody enrichments + venue mesh + PoR, still with live gates default-off.
- R8. The 12 Top50 improvement functions are the **install knobs** for each `X-*` enrichment (performance, security, reliability, capacity, latency, throughput, monitoring, auto-recovery, caching, logging, analytics, algorithm).

## Train F — Exchange Mega enrichments → **v32.6.6.0**

Install the Top50 techs again as **exchange-wallet enrichments** (`X-01`…`X-50`). Each enrichment can take the 12 improvement functions as install knobs.

### Install knobs (per enrichment)

1. `optimize_performance` — faster order/quote/RPC path  
2. `enhance_security` — tighter ACL / signing / withdraw policy  
3. `improve_reliability` — retries, idempotency, dual-write safety  
4. `scale_capacity` — more open orders / venues / sockets  
5. `reduce_latency` — bookTicker / fill notify lag down  
6. `increase_throughput` — batch settles, parallel venue reads  
7. `add_monitoring` — exchange health tiles + alerts  
8. `enable_auto_recovery` — reconnect / resubscribe / rewind  
9. `improve_caching` — book + balance cache with TTL  
10. `enhance_logging` — structured trade/settle audit log  
11. `add_analytics` — PnL / fee / slippage analytics  
12. `upgrade_algorithm` — smarter fee, routing, sizing
