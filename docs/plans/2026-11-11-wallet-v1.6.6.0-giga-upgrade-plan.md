# Wallet v1.6.6.0 — Giga Upgrade Plan

## Goal Capsule

- **Objective:** Ship **MasterNoder2 Wallet v1.6.6.0** as a giga upgrade that turns the documented Top 50 agent technologies into real wallet / daemon / Qt / web capabilities people can feel.
- **Means:** Map each of the 50 techs into a concrete wallet surface (daemon RPC, Qt UI, `/wallets` + profile wallet, sporks, monitoring). Land them in four version trains that culminate in **1.6.6.0**.
- **Authority:** Product behavior wins over agent-scaffold leftovers. Do not ship empty `/api/agent-tech/*` stubs as the wallet upgrade.
- **Execution:** Daemon + Qt live in the MasterNoder2 release line; web/API glue and download manifests live in this repo.
- **Stop:** Stop if a work item requires turning `SPORK_112` / `SPORK_113` / `SPORK_114` live by default, or if it mixes unrelated frontpage entertainment into the wallet binary.

## Why 1.6.6.0

| Today | Gap | 1.6.6.0 |
| ----- | --- | ------- |
| Wallet downloads at **mn2-wallet-v1.3.0.0** | Big jump past 1.4/1.5 needs a story | Version train 1.4 → 1.5 → 1.6 → **1.6.6.0 giga ship** |
| Daemon **v1.3.1.0** (exchange/casino/payout/maintenance sporks) | Sporks exist; wallet UX still thin | Tech pillars become wallet features + new optional sporks only when gated |
| Top 50 techs exist as agent docs / DB schema | Mostly platform/agent scaffolding | Each tech maps to one wallet deliverable |

Source catalog: `docs/50_AGENT_TECHS_COMPLETE.md` (50 techs × 12 improvement functions).

## Non-goals

- Re-implementing 600 empty improvement functions inside `masternoder2d`.
- Replacing the existing exchange/casino product with agent buzzwords.
- Bundling lobby monitor / Jon Film / camgirl work into the wallet tarball.

## Product Contract

### Summary

A person running Wallet **v1.6.6.0** gets a hardened, observable, self-healing MN2 wallet: faster sync and RPC, safer keys and spend paths, live health/alerts, smart fee and anomaly help, and a web/Qt surface that mirrors Top25-grade telemetry without requiring agent dashboards.

### Requirements

- R1. Every Top50 tech maps to exactly one wallet deliverable ID (`W-01`…`W-50`) with owner surface: `daemon` | `qt` | `web` | `ops`.
- R2. Version trains ship: **1.4.0.0** (core rail), **1.5.0.0** (tools + scanners), **1.6.0.0** (monitors + navigation), **1.6.6.0** (advanced intelligence + integration + release).
- R3. `/wallets` and release manifests advertise **v1.6.6.0** with sha256 for daemon + Qt linux/win when the giga tag ships.
- R4. Existing sporks 112–115 stay human-gated; any new gate is optional and default-off.
- R5. Each train has falsifiable acceptance: RPC smoke, Qt smoke, web download row, and one regression suite.

| Risk | Mitigation |
| ---- | ---------- |
| Top50 docs are agent scaffolds, not wallet code | Mapping table is the contract; implement wallet deliverables, ignore empty stubs |
| Version jump confuses operators mid-train | Publish intermediate 1.4 / 1.5 / 1.6 tags; only promote site “Latest” at 1.6.6.0 |

| Scope explodes into platform rewrite | Stop rule: wallet binary + wallets surface only |
